# Tresor Plugins

JavaScript API V2 and V3 plugins for [Tresor](https://github.com/Ladbaby/Tresor), an LLM gateway. Plugins are opt-in routing-rule transformations; API format conversion is managed by Tresor itself.

## Plugins

| Plugin | Version | Purpose |
| --- | --- | --- |
| `break_repeat` | 2.0.4 | Inserts a user reminder when the last three comparable assistant turns are identical; thinking/reasoning blocks are excluded from the comparison, the reminder merges into the trailing user turn, and format detection is based on content shape. |
| `fix_anthropic_system` | 2.0.1 | Moves system-role messages into Anthropic's top-level system field, preserving instruction groups and cache metadata. |
| `fix_anthropic_usage` | 2.0.2 | Normalizes incomplete Anthropic usage blocks and synthesizes missing delta fields from the latest observed counters. |
| `force_streaming` | 2.0.2 | Requests upstream SSE for buffered clients and reconstructs OpenAI, Anthropic, Responses, or Gemini JSON responses, preserving custom tools and part boundaries. |
| `opencode-go` | 1.0.1 | Speaks to OpenCode Zen/Go gateways as OpenCode 1.19.0 does: synthesizes the `x-opencode-*` session/request headers with a stable per-conversation session id (engine KV store, atomic get-or-set), strips foreign session headers, and serves the free tier its streamed `bash`/`read` tool stubs with the `/zen`→`/inference` rewrite. |
| `remove_thinking` | 2.0.2 | Removes thinking/reasoning response content while preserving visible content and tool inputs. |
| `tresorbot/bridge` | 1.0.0 | Bridges a request to a TresorBot service and exposes that service's scoped durable-memory tools to the model. Requires rule step configuration. |

Use a Tresor build supporting plugin API V2 or V3 and the features declared in each plugin's `manifest.json`. 

## Remote installation

Downloadable packages are **JSON bundles generated by `tresor plugin pack`**, not repository ZIP files or individual JavaScript sources. When published, versioned bundles and canonical source digests are available on the [Releases page](https://github.com/Ladbaby/Tresor-plugins/releases).

With your Tresor daemon running, replace `RELEASE_TAG`, `ASSET`, and `CANONICAL_DIGEST` with values from the chosen release (`plugin-digests.txt` on each release lists every asset with its digest):

```powershell
.\tresor.exe plugin install-url "https://github.com/Ladbaby/Tresor-plugins/releases/download/RELEASE_TAG/ASSET" --sha256 "CANONICAL_DIGEST" --config "./config.yaml"
```

For example, the current API V3 bridge:

```powershell
.\tresor.exe plugin install-url "https://github.com/Ladbaby/Tresor-plugins/releases/download/v1.0.3/tresorbot-bridge-1.0.0.json" --sha256 "d7cb6f75e661ebde20f3bdff7ac098bce4629a9399bbadccc7ee2d35faa558c2" --config "./config.yaml"
```

The expected digest is the **canonical source digest emitted by Tresor**, not a checksum of the downloaded JSON file. Installation enables the plugin immediately; no permission approval or separate activation is needed. Add it to a routing rule's pipeline before it applies to requests.

Alternatively, open **Rules > Plugins** in the Tresor dashboard, install the release asset's HTTPS URL, then add it to a rule.

Manage installed versions with `plugin enable <id> <version>`, `plugin disable <id> <version>`, and `plugin delete <id> <version>`.

Only install plugin code from sources you trust. HTTPS alone does not establish a verified publisher signature. An expected digest checks that the package matches the digest you supplied; obtain that digest from a trusted source.

## Rule step configuration

Most API V2 plugins take no configuration: add them to a rule pipeline and they apply.

API V3 plugins declare a `config_schema`, and each rule pipeline step carries its own `config` object, so the same plugin can point at different services in different rules. `tresorbot/bridge` requires `sun_url`, `service_token`, and `control_token` in its step config, and binds them to its `local` service for the `prepare`, `invoke`, and `execute-tool` operations. Credentials stay in that step; there are no global service or grant settings. Service base URLs must use HTTPS, or HTTP only on loopback.

```yaml
rules:
  - id: sun-bridge
    name: Sun Bridge
    pattern_path: /v1/chat/completions
    match_format: [openai]
    pipeline_config:
      - plugin_id: tresorbot/bridge
        config:
          sun_url: "http://127.0.0.1:8787"
          service_token: "..."
          control_token: "..."
    is_enabled: true
```

The same fields appear in the dashboard's rule editor when the step is added.

## Local authoring and packaging

Each plugin lives in its own directory containing `manifest.json`, the entry JavaScript file, and any additional modules. From this repository, using a sibling Tresor checkout:

```powershell
New-Item -ItemType Directory -Force dist | Out-Null
..\Tresor\tresor.exe plugin lint ./remove_thinking
..\Tresor\tresor.exe plugin pack ./remove_thinking --output ./dist/remove_thinking-2.0.2.json
```

Lint and pack do not execute JavaScript. Lint findings are advisory unless `--strict` is supplied; lint is not a compatibility proof. Pack prints the canonical source digest and refuses to overwrite an existing output file.

Bump a plugin's manifest version whenever publishing changed source. Keep generated bundles in GitHub Releases rather than committing `dist/`, and retain versioned asset URLs for reproducible installation.
