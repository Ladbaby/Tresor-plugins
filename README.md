# Tresor Plugins

JavaScript API V2 plugins for [Tresor](https://github.com/Ladbaby/Tresor), an LLM gateway. Plugins are opt-in routing-rule transformations; API format conversion is managed by Tresor itself.

## Plugins

| Plugin | Version | Purpose |
| --- | --- | --- |
| `break_repeat` | 2.0.1 | Inserts a user reminder when the last three assistant messages are identical. |
| `fix_anthropic_system` | 2.0.1 | Moves system-role messages into Anthropic's top-level system field, preserving instruction groups and cache metadata. |
| `fix_anthropic_usage` | 2.0.1 | Normalizes incomplete Anthropic usage blocks and synthesizes missing message-delta usage from message-start counts. |
| `force_streaming` | 2.0.1 | Requests upstream SSE for buffered clients and reconstructs OpenAI, Anthropic, Responses, or Gemini JSON responses. |
| `remove_thinking` | 2.0.2 | Removes thinking/reasoning response content while preserving visible content and tool inputs. |

Use a Tresor build supporting plugin API V2 and the features declared in each plugin's `manifest.json`. 

## Remote installation

Downloadable packages are **JSON bundles generated by `tresor plugin pack`**, not repository ZIP files or individual JavaScript sources. When published, versioned bundles and canonical source digests are available on the [Releases page](https://github.com/Ladbaby/Tresor-plugins/releases).

With your Tresor daemon running, replace `RELEASE_TAG` and `CANONICAL_DIGEST` with values from the chosen release:

```powershell
.\tresor.exe plugin install-url "https://github.com/Ladbaby/Tresor-plugins/releases/download/RELEASE_TAG/remove_thinking-2.0.2.json" --sha256 "CANONICAL_DIGEST" --config "./config.yaml"
```

The expected digest is the **canonical source digest emitted by Tresor**, not a checksum of the downloaded JSON file. Installation enables the plugin immediately; no permission approval or separate activation is needed. Add it to a routing rule's pipeline before it applies to requests.

Alternatively, open **Rules > Plugins** in the Tresor dashboard, install the release asset's HTTPS URL, then add it to a rule.

Manage installed versions with `plugin enable <id> <version>`, `plugin disable <id> <version>`, and `plugin delete <id> <version>`.

Only install plugin code from sources you trust. HTTPS alone does not establish a verified publisher signature. An expected digest checks that the package matches the digest you supplied; obtain that digest from a trusted source.

## Local authoring and packaging

Each plugin lives in its own directory containing `manifest.json`, the entry JavaScript file, and any additional modules. From this repository, using a sibling Tresor checkout:

```powershell
New-Item -ItemType Directory -Force dist | Out-Null
..\Tresor\tresor.exe plugin lint ./remove_thinking
..\Tresor\tresor.exe plugin pack ./remove_thinking --output ./dist/remove_thinking-2.0.2.json
```

Lint and pack do not execute JavaScript. Lint findings are advisory unless `--strict` is supplied; lint is not a compatibility proof. Pack prints the canonical source digest and refuses to overwrite an existing output file.

Bump a plugin's manifest version whenever publishing changed source. Keep generated bundles in GitHub Releases rather than committing `dist/`, and retain versioned asset URLs for reproducible installation.
